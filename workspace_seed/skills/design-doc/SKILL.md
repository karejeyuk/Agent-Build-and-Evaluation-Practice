# 목적
착수가 확정된 업무의 설계서 초안을 고정 목차로 쓴다(기획서 3.7).

# 작업 지침
- 9목차 구조를 지키고, 목차를 더하거나 빼거나 옮기지 않는다.
- 업무 사실(절차, 시스템, 예외, 실수 영향)에는 카드의 근거를 인용한다.
- B1형이거나 오류 영향도 1~2점이면 워크플로에 사람 승인 지점을 반드시 넣는다.

# 실행 순서
작업 공간 루트에서 실행한다. 업무마다 한 번씩 실행한다.
1) `python3 core/run.py start design-doc --ranking <outputs/…_3단계_….md> --card <카드 번호> [--dept <영업부>]`
   - 순위표의 모든 업무에 엔지니어 확정이 규칙대로 적혀 있고, 이 카드가 즉시 착수나 검토 후 착수로 확정돼 있어야 시작한다.
2) 안내된 호출 패키지를 읽고 설계서 JSON을 저장한 뒤 `python3 core/run.py submit <run_id>`를 실행한다.
3) 다시 만들기 요청(종료 코드 3)이면 실패 항목만 고쳐 한 번 더 submit한다. 차단(종료 코드 2)이면 메시지를 엔지니어에게 전하고 멈춘다.
4) 완료되면 산출물 경로, 품질 게이트 결과, 필수 승인 지점 여부, 경고를 알린다.

# 품질 기준과 실패 처리
기획서 3.7의 작성 규칙, 품질 기준, 예외 상황과 5.4의 검증 항목을 따른다. 목차 누락, 근거 없는 업무 사실, 필수 승인 지점 누락, 문체 위반은 한 번 다시 만든다. 그래도 통과하지 못하면 경고를 단 채 산출하고, 필수 승인 지점이 빠진 설계서는 엔지니어가 승인하지 않는다. 품질 게이트(세부 항목 19개 가운데 6개 이상 미확인이면 '2단계 인터뷰 보강 권고')는 다시 만들지 않고 결과만 표시한다.

# 엔지니어 확정
상단 '엔지니어 확정' 줄에 `승인`을 적은 설계서로 PoC를 구현한다. report의 입력도 승인된 설계서만 쓴다.
