# 목적
확정된 카드를 평가 기준표로 채점하고 착수 우선순위를 제안한다(기획서 3.6).

# 작업 지침
- 점수, 총점, 등급, 절감 시간은 코드가 계산한 값만 쓰고 바꾸지 않는다.
- 근거는 카드 필드 값 뒤에 붙은 인용이나 0단계 시스템·데이터 원천 정리의 문서 근거를 그대로 옮긴다.
- 고객사에 건네는 문장은 존댓말로 쓴다.

# 실행 순서
작업 공간 루트에서 실행한다.
1) `python3 core/run.py start fit-scoring --cards <outputs/…_2단계_….md> [--cards …] [--pre-research <outputs/…_0단계_….md>] [--dept <영업부>]`
   - 넣은 2단계 산출물의 모든 카드에 엔지니어 확정이 규칙대로 적혀 있어야 시작한다. 하나라도 비었거나 변경 사유가 빠졌으면 차단된다.
   - 코드가 업무마다 최신 회차 카드를 고르고, 확정 값이 A형·B1형이면 채점 대상, B2형이면 표준화 선행 권고 대상으로 나눈다.
2) 1/2단계 패키지(칸 선택)를 읽고 JSON을 저장한 뒤 submit한다. 코드가 반복성, 점수, 총점, 등급, 상한 규칙, 절감 시간을 계산하고 요약 대상(최대 3개)을 고른다.
3) 요약 대상이 있으면 2/2단계 패키지(추천 근거 요약)를 읽고 JSON을 저장한 뒤 submit한다. 없으면 코드가 바로 순위표를 저장한다.
4) 다시 만들기 요청(종료 코드 3)이면 실패 항목만 고쳐 한 번 더 submit한다. 차단(종료 코드 2)이면 메시지를 엔지니어에게 전하고 멈춘다.
5) 완료되면 산출물 경로, 등급 제안, 경고를 알리고 엔지니어의 업무별 확정을 기다린다.

# 품질 기준과 실패 처리
기획서 3.6의 품질 기준과 5.4의 검증 항목을 따른다. 칸 선택의 근거는 카드나 0단계 정리에 이미 붙은 인용과 대조한다. 다시 만든 뒤에도 근거 인용이 없거나 대조에 실패한 칸 선택은 받지 않고 그 기준을 [확인 필요]로 둔다(그 업무는 평가 불가가 된다). 확인되지 않은 빈도나 소요 시간에서는 수치를 계산하지 않는다.

# 엔지니어 확정
순위표 '엔지니어 확정' 칸에 업무마다 확정 값을 적는다. 제안과 다르면 같은 칸에 '(변경 사유: …)'를 덧붙인다. 평가 불가 업무는 다음 회차 확인이나 착수 보류로만 확정할 수 있다. 상한 규칙은 엔지니어 확정보다 우선하므로 오류 영향도 1~2점 업무는 즉시 착수로 확정할 수 없다. 즉시 착수나 검토 후 착수로 확정한 업무만 design-doc의 입력으로 쓴다.
