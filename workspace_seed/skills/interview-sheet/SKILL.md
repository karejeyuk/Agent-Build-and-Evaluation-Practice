# 인터뷰 가이드 생성

0단계 사전 조사 결과와 담당자 프로필을 받아, 엔지니어가 검토하고 승인할 인터뷰 시트나 메일 질문지 초안을 만든다. 실제 인터뷰는 사람이 진행한다.

## 입력 준비

엔지니어가 제공한 정보를 사용한다.

- 담당자 프로필 JSON: `부서`, `직무명`, `직급`, `담당 업무`, `연차`
- 인터뷰 조건: `대면` 또는 `온라인`이면 30분이나 60분, `메일`이면 시간은 사용하지 않음
- 선택 입력: 검토 완료된 사전 조사 요약서와 엔지니어가 정리한 직전 회차 확인 목록 JSON
- 출처, 인터뷰 식별자(아직 없으면 `[확인 필요: 인터뷰 식별자]`), 실행 버전

실제 고객사 자료를 사용하는 경우 LLM 입력 전에 고객사 허용과 가명 처리를 확인한다. 가명 매핑표와 원본은 LLM에 입력하지 않는다. 정보가 비어 있으면 값을 지어내지 말고 템플릿의 확인 표시를 유지한다.

## 실행 절차

1. 담당자 프로필과 인터뷰 조건을 확인한다. 확인 목록은 v1에서 엔지니어가 직접 정리해 제공한다.
2. 필요하면 사전 조사 요약서의 YAML front matter에 있는 `followup_items`와 확인 목록 JSON을 준비한다. 확인 목록 항목은 `{"kind":"이월|다음회차확인|문서후보|확인필요|정보부족","content":"...","f_numbers":["F1"]}` 형식을 쓴다.
3. 작업 공간 기준으로 `python3 skills/interview-sheet/build_sheet.py allocate --profile <프로필.json> --format <interview|mail> --duration <30|60> --round <1|2> [--pre-research <사전조사.md>] [--followup <확인목록.json>]`를 실행한다. 메일 형태에는 `--duration`을 생략한다. 결과 JSON의 `materials`가 LLM에 넘길 재료이며, 항목 수는 코드가 고정한다.
4. `prompts/custom_questions.md`의 지시에 따라 `materials` 항목마다 질문 문장 하나씩만 만든다. 질문 번호를 붙이지 말고 JSON 배열로 반환한다.
5. 질문 배열을 JSON 파일로 저장하고 `python3 skills/interview-sheet/build_sheet.py build --plan <배분결과.json> --questions <질문.json> --source <출처> --interview-id <식별자> --execution-version <버전> --output <출력.md>`를 실행한다. 메일 질문지에서는 엔지니어용 부록을 포함하고, F번호를 담당자에게 보이는 본문에 넣지 않는다.
6. 출력 파일을 읽어 고정 문구, 질문 개수, F번호 부록, 출처와 엔지니어 확정란을 확인한다. 코드 검증을 실행하지 않았으면 검증 완료라고 표시하지 않는다.

## 배분 규칙

- 30분 대면·온라인: 필수 확인 주제 3개, 사전 조사 확인 항목 최대 2개. 사전 조사 항목이 모자라면 필수 확인 주제 4·5번째로 채워 총 5개를 만든다.
- 60분 대면·온라인: 필수 확인 주제 5개, 사전 조사 확인 항목 최대 5개. 남은 자리는 필수 확인 주제를 심화한 재료로 채워 총 10개를 만든다.
- 1회차 메일: 사전 조사 확인 항목 1개와 필수 확인 주제 첫 번째를 쓴다. 사전 조사 항목이 없으면 필수 확인 주제 앞의 2개를 쓴다.
- 2회차 이상: 확인 목록을 종류 우선순위(이월, 다음회차확인, 문서후보, 확인필요, 정보부족)로 먼저 배분하고 남는 자리는 필수 확인 주제, 심화 주제 순으로 채운다. 같은 내용은 합치고 F번호를 보존한다.
- 사전 조사나 확인 목록에서 배분하지 못한 항목은 다음 회차 이월 목록에 남긴다. 코드는 배분과 질문 수를 결정하며 LLM은 질문 문장만 쓴다.

## 산출물과 확정

- 대면·온라인: 인트로, 공통 질문 8개, 직무 맞춤 질문, 다음 회차 이월 블록, 심화 후속 질문, 마무리 체크리스트 순서의 인터뷰 시트
- 메일: 인사말, 작성 안내, 서술형 공통 질문 8개, 맞춤 질문 2개, 회신 기한 안내, 엔지니어용 부록
- 모든 출력은 초안이며, 엔지니어 확정은 `사용 승인`으로 비워 둔다.
