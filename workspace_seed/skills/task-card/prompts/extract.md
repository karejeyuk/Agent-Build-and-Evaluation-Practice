# 업무 카드 추출

입력: 화자 표지가 있는 인터뷰 원문, 선택적 검토 완료 사전 조사 요약서, `rules.md`, 카드 필드 정의.

업무마다 다음을 지킨다.

- 주기 또는 발생 사건, 동작, 대상이 확인되면 카드의 추출 근거에 각각 적는다. 사건이나 주기가 문맥에 없더라도 동작과 대상이 명확하면 카드를 만들고 빈도는 `[확인 필요: 빈도]`로 둔다.
- 같은 주기·사건에 이어지는 작업은 한 카드에 절차 순서로 적는다. 조건 때문에 동작이나 대상이 바뀌면 사건 기반 카드로 나눈다. 현장 작업은 대체하지 말고 그에 딸린 기록·보고 업무만 카드화한다.
- 다른 사람이 맡는 판단 업무는 별도 카드로 분리한다. 나머지 판단은 해당 카드의 절차 단계로 기록한다.
- 문서에만 있고 인터뷰에서 확인되지 않은 업무는 카드로 만들지 않고 `document_candidates`에 둔다.
- 각 사실 필드는 근거 객체를 붙인다. 발화 근거는 `{source_type:"utterance", q:"Q2", speaker:"담당자", quote:"원문 연속 발췌"}` 또는 메모 `{source_type:"memo", m:"M1", quote:"원문 연속 발췌"}`다. 문서 근거는 `{source_type:"document", filename:"파일명", start_line:1, end_line:2, quote:"해당 줄의 연속 발췌"}`다.
- 분류, 판단 개입 지점, 10번 미확인 항목은 비워 둔다. 형을 선택하지 않는다.
- 출력은 JSON 객체만 반환한다. 부연 설명과 코드 펜스는 금지한다.

JSON 계약:
`{"cards":[{"card_id":"","work_key":"업무 식별용 이름","extraction_basis":{"trigger":"","action":"","object":""},"fields":{"1":"업무명","2":"","3":"빈도·소요 시간","4":"사용 시스템","5":"절차 요약","6":"예외 상황","7":"실수 영향","8":"","9":"근거 원문","10":""},"field_evidence":{"3":[],"4":[],"5":[],"6":[],"7":[],"9":[]}}],"document_candidates":[{"name":"","evidence":[]}],"standardization_recommendations":[]}`

모르는 필드는 `[확인 필요: 구체 항목]`으로 남기고 지어내지 않는다.
