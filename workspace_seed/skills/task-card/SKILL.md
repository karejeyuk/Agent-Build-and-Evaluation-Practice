# 목적
인터뷰 원문을 업무 상세 카드로 바꾸고, 형 판정에 필요한 조건표를 만든다(기획서 3.5).

# 작업 지침
- 형을 고르지 않는다.
- 인용은 원문에서 이어진 한 구간을 글자 그대로 옮긴다. 발화 인용은 담당자 줄(메모는 M 문단)에서, 긍정 답 인용은 같은 Q번호의 면담자 줄과 담당자 줄을 이은 문자열에서, 문서 인용은 요약서 발췌의 줄 범위에서 가져온다.
- 답을 듣지 못한 내용은 [확인 필요: 내용]으로 둔다.

# 실행 순서
작업 공간 루트에서 실행한다.
1) `python3 core/run.py start task-card --interview-id <A사-영업-01-1회차> --transcript <inputs/…txt 또는 tests/…txt> [--pre-research <outputs/…_0단계_….md>] [--dept <영업부>] [--stt-review]`
   - 원문은 엔지니어가 `Q1 면담자: …`, `Q1 담당자: …`처럼 질문 번호와 화자 표지를 붙인 텍스트다(질문 없는 메모는 문단마다 `M1: …`). 표지가 없으면 시작하지 않는다.
   - 0단계 요약서는 `검토 완료`로 확정된 것만 받는다.
2) 1/2단계 패키지(카드 추출)를 읽고 JSON을 저장한 뒤 submit한다. 코드가 카드 번호를 매기고 인용을 대조한다.
3) 2/2단계 패키지(판정 조건표)를 읽고 JSON을 저장한 뒤 submit한다. 코드가 형을 정하고 카드를 조립해 저장한다.
4) 각 단계에서 다시 만들기 요청(종료 코드 3)이 오면 새 패키지의 실패 항목만 고쳐 한 번 더 submit한다. 차단(종료 코드 2)이면 메시지를 엔지니어에게 전하고 멈춘다.
5) 완료되면 산출물 경로, 카드별 분류 제안, 경고를 알리고 엔지니어의 카드별 확정을 기다린다.

# 품질 기준과 실패 처리
기획서 3.5의 품질 기준, 예외 상황, 다시 만들기 규칙과 5.4의 검증 항목을 따른다. 인용이 다른 Q번호·M 문단·줄 범위에 있으면 코드가 번호를 고치고 경고를 남긴다. 인용 전체가 면담자 줄 안에 있거나 원문에 없으면 실패 항목만 한 번 다시 만든다. 다시 만든 뒤에도 실패한 충족 조건은 '미충족(인용 대조 실패)'으로 적고 [판정 보류: 인용 대조 실패]가 된다. 근거 없는 사실 필드 값은 [확인 필요]로 바꾸고 경고를 단다. 문체는 경고만 단다.

# 엔지니어 확정
카드마다 '엔지니어 확정:' 줄에 A형, B1형, B2형, C형, 다음 회차 확인 가운데 하나를 적는다. 제안과 다르게 확정하면 바로 아래에 '변경 사유:' 줄을 적는다(판정 보류 제안을 다음 회차 확인으로 확정할 때는 사유가 필요 없다). 모든 카드가 확정된 산출물만 fit-scoring의 입력으로 쓴다.
