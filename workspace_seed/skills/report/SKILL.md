# 목적
프로젝트마다 반복되는 성과 리포트 초안을 만든다(기획서 3.8).

# 작업 지침
- 실측치에는 (실측), 추정치에는 (추정), 성공 정의의 목표치에는 (목표)를 붙인다.
- 피드백 원문은 가명 처리된 그대로 옮긴다.
- 임원용 1쪽 요약은 고객사에 건네는 글이므로 존댓말로 쓴다.

# 실행 순서
작업 공간 루트에서 실행한다. 업무(설계서)마다 한 번씩 실행한다.
1) `python3 core/run.py start report --design <outputs/…_4단계_….md> --measurements <inputs/실측.csv 또는 .json> [--feedback <inputs/피드백.txt>] [--dept <영업부>]`
   - 설계서는 엔지니어가 `승인`한 것만 받는다.
   - 실측 데이터는 `항목,값` CSV나 `{"항목": 값}` JSON이다. 사람 개입률 항목(이름에 '개입률')이 있으면 코드가 3단계 참고 정보와 함께 절감 시간 추정치를 계산한다.
2) 안내된 호출 패키지를 읽고 리포트 JSON을 저장한 뒤 `python3 core/run.py submit <run_id>`를 실행한다.
3) 다시 만들기 요청(종료 코드 3)이면 실패 항목만 고쳐 한 번 더 submit한다. 차단(종료 코드 2)이면 메시지를 엔지니어에게 전하고 멈춘다.
4) 완료되면 산출물 경로와 경고를 알리고 엔지니어의 수치 확정을 기다린다.

# 품질 기준과 실패 처리
기획서 3.8의 품질 기준과 예외 상황, 5.4의 검증 항목(5단계 수치 표기와 피드백 인용, 문체)을 따른다. 실측치는 실측 데이터와, 목표치는 설계서의 성공 정의와, 피드백 인용은 피드백 원문과 대조한다. 임원용 요약의 수치마다 표기가 붙었는지 본다. 통과하지 못하면 한 번 다시 만들고, 그래도 실패하면 실측을 [측정 불가]로 두거나 인용을 빼고 경고를 남긴다.

# 엔지니어 확정
수치를 확인한 뒤 상단 '엔지니어 확정' 줄에 `수치 확정`을 적은 리포트를 고객사 보고에 쓴다.
