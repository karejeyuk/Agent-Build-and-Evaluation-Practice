# 목적
인터뷰 전에 문서로 알 수 있는 업무를 정리해 맞춤 질문 재료를 만든다(기획서 3.3).

# 작업 지침
- 문서에 있는 서술만 옮기고, 문서에 없는 업무를 더하지 않는다. 문서에 없는 담당자·빈도·절차를 추정하지 않는다.
- 모든 항목에 문서 근거를 붙인다. 인용은 번호가 붙은 문서에서 이어진 한 구간을 글자 그대로 옮기고 중간을 줄이지 않는다.
- 절차가 적혀 있으면 그 서술을 그대로 발췌한다.

# 실행 순서
작업 공간 루트에서 실행한다. 경로는 `inputs/…`(실제 고객사 가명 처리본) 또는 `tests/…`(가상 시나리오)로 준다.
1) `python3 core/run.py start pre-research --interview-id <A사-영업-01-1회차> [--profile <프로필.json>] [--dept <영업부>] [--document <문서.txt> …]`
   - 문서가 없으면 LLM을 부르지 않고 '사전 자료 없음' 형식의 산출물을 바로 저장하고 끝난다.
2) 출력이 안내하는 호출 패키지 파일을 read_file로 모두 읽고, 지시한 JSON만 만들어 안내한 경로에 write_file로 저장한다.
3) `python3 core/run.py submit <run_id>`를 실행한다. 다시 만들기를 요청하면(종료 코드 3) 새 패키지를 읽고 실패 항목만 고쳐 다시 저장한 뒤 submit한다. 다시 만들기는 한 번뿐이다.
4) 완료되면 `outputs/`에 저장된 파일 경로와 경고를 엔지니어에게 알리고, 확정을 기다린다. 확정란은 엔지니어가 직접 적는다.
- 종료 코드 2(차단)는 엔지니어 확인이 필요하다는 뜻이다. 메시지를 그대로 전하고 멈춘다.

# 품질 기준과 실패 처리
기획서 3.3의 품질 기준과 예외 상황, 5.4의 검증 항목을 따른다. 발췌가 다른 줄 범위에 있으면 코드가 줄 번호를 고치고 경고를 남긴다. 다시 만든 뒤에도 근거 대조에 실패한 항목은 산출물에서 빼고 경고로 남긴다. 텍스트로 읽을 수 없는 문서는 [확인 필요: 텍스트 추출 실패, 원본 수동 확인]으로 표시하고 나머지 문서만 처리한다.

# 엔지니어 확정
상단 '엔지니어 확정' 줄에 `검토 완료`를 적은 요약서만 interview-sheet, task-card, fit-scoring의 입력으로 쓴다.
