# 사전 조사 정리

인터뷰 전에 받은 부서 문서에서 확인할 수 있는 업무 사실을 정리한다. 문서에 없는 절차나 담당자를 추측하지 않는다. v1은 텍스트 파일만 처리한다.

## 실행 절차

1. 사용자가 지정한 문서만 입력으로 사용한다. 실제 고객사 자료는 고객사 사용 허용과 가명 처리 여부를 먼저 확인한다. 가명 매핑표나 원본은 LLM에 넣지 않는다.
2. 문서가 없으면 `python3 skills/pre-research/prepare_documents.py`를 실행해 일반형 플래그를 만들고, LLM을 호출하지 않는다.
3. 문서가 있으면 다음처럼 번호를 붙인 JSON을 만든다. 명령은 workspace 루트에서 실행한다.

   `python3 skills/pre-research/prepare_documents.py --document <텍스트파일> [--document <텍스트파일>] --output <번호붙인문서.json>`

   출력의 `documents[].numbered_text`에 L1부터 시작하는 줄 번호가 들어간다. 이미지·스캔본·지원하지 않는 바이너리는 읽었다고 간주하지 않고 확인 필요로 남긴다.
4. 번호가 붙은 문서와 `templates/pre_research.md`를 읽고 `prompts/extract.md`의 지시에 따라 요약 초안을 작성한다. 각 문서 근거는 원문 발췌를 그대로 포함한다.
5. 요약서 front matter에는 아래 기계 판독용 자료도 채운다.

   `status: reviewed`
   `followup_items:`
   `  - content: 업무 또는 누락 정보`
   `    missing_fields: [빈도, 담당자, 사용 시스템, 절차 중 누락 항목]`

   사전 조사 확인 항목은 문서에 업무가 명시되어 있으나 빈도·담당자·사용 시스템·절차 중 하나 이상이 빠진 경우에만 넣는다.
6. 파일 도구로 `outputs/` 아래 새 Markdown 파일에 작성한다. 기존 파일을 덮어쓰지 않는다. 코드가 출력한 줄 번호를 포함한 모든 문서 근거를 `python3 skills/pre-research/validate_excerpts.py --documents <번호붙인문서.json> --report <요약서.md>`로 대조한다. 검증에 실패하면 실패한 인용만 원문과 대조해 고치고 다시 실행한다.
7. 이미지나 스캔본이 섞여 있으면 해당 항목에 `[확인 필요: 텍스트 추출 실패, 원본 수동 확인]`을 기록하고, 읽을 수 있는 텍스트 문서는 계속 처리한다.

## 경로 B: 사전 자료 없음

문서 없이 담당자 프로필만 있는 경우 LLM을 호출하지 않는다. 코드가 만든 `status: no_pre_research` 플래그와 `templates/pre_research.md`를 이용해 '사전 자료 없음, 사전 조사 기반 질문 제외' 산출물을 만든다. 문서 근거는 쓰지 않는다.

## 품질과 확정

- 문서에 적힌 업무만 후보에 넣는다. 문서에 있는 절차는 가능한 한 원문 그대로 발췌한다.
- 문서 근거는 파일명, 해당 줄 범위, 이어진 원문 발췌로 쓴다. 발화 근거와 섞지 않는다.
- 산출물 상단의 인터뷰 식별자와 실행 버전이 미정이면 `[확인 필요: ...]`로 둔다.
- 이 결과는 초안이다. 엔지니어가 `검토 완료`로 확정한 요약서만 이후 단계의 입력으로 쓴다.
